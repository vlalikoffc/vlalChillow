# Тест страницы панели

Страница панели — единственный JS в проекте, и она вшивается в сборку как
`EmbeddedResource` (`server/Web/wwwroot/index.html`). Этот тест проверяет её в jsdom
без сервера и без сети: `fetch` замокан ответами `WebPanelRouter`.

```bash
npm install --prefix /tmp/paneltest jsdom
NODE_PATH=/tmp/paneltest/node_modules node tests/panel/panel.test.js
```

Выход `0` — все проверки зелёные, `1` — есть провалы (список печатается).

## Что проверяется

- каталог режимов и карт приходит с `/api/modes`, копии в JS нет;
- «Все режимы» выбрано явно — фильтр не прячет комнаты по умолчанию;
- фильтры по режиму и карте реально сужают список;
- создание комнаты — один POST, номер выдаёт сервер, а не страница;
- занятый ник, частота, неизвестный режим показываются понятным текстом;
- имя комнаты экранируется (XSS через чужой ввод);
- комната в состоянии `finished` не предлагает войти;
- при `gameListening: false` появляется предупреждение, что игровой порт не поднят.

## Почему не в CI

`jsdom` — единственная dev-зависимость, и она не нужна для сборки сервера.
В CI страницу проверяет `WebPanelRouterTests` на стороне C#: маршруты, статусы и JSON —
именно те места, где ошибка ломает не внешний вид, а работу кнопки.
