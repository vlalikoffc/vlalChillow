# Комнаты и веб-панель — полный план

Документ фиксирует **весь** объём работ, чтобы шаги не потерялись между сессиями.
Статусы обновляются по мере реализации.

- **Ветка:** `arena/ddbade03-vlalchillow` (база `5ffa6be`)
- **Главное ограничение:** провод (UDP) **не меняется ни на байт** — ни опкода, ни поля,
  ни порта, ни тайминга. Всё ниже — серверная маршрутизация, конфиг и новый слой `server/Web/`.

---

## Что делаем по-человечески

Сейчас сервер = одна катка на UDP 7777. Нужно: **несколько комнат на том же порту 7777**,
создание комнат с веб-панели, вход командой `/join <режим> #<номер>` из лобби.

```
браузер ──HTTPS──> nginx (example.com) ──HTTP 127.0.0.1:8080──> наш exe ──> RoomRegistry
                                                              │
телефон ──UDP 7778 лобби──> /join 2v2 #3 ─────────────────────┘
телефон ──UDP 7777 матч──────────────────────────┘ (порт тот же, комната выбирается сервером)
```

## Ключевое техническое решение (доказано по коду)

Клиент нельзя заставить сменить порт — он идёт туда, что сервер прислал в `op9`, а живой клиент
всегда на 7777. Значит **комнаты живут внутри одного `GameMatchHost`** — это уже почти есть:

| Что | Где | Статус |
|---|---|---|
| Словарь комнат | `GameMatchHost._roomsByPassword` | **есть** |
| Создание комнаты по ключу | `EnsureRoom(passwordKey, roomId)` | **есть** |
| Обход всех комнат в тике | `TickMatchFlow()` → `_roomsByPassword.Values` | **есть** |
| Изоляция рассылки | `BroadcastRoom` проверяет `st.Room != room` | **есть** |
| Поиск комнаты при входе | `_roomsByPassword.TryGetValue(req.Password)` | **есть**, но ищет по паролю `Dedik` |
| Режим/карта комнаты | `room.ActorProps[(0, C0)] / [(0, C1)]` | **есть** |
| **Выбор комнаты сервером** | — | **нет** → добавляем |
| **Жизненный цикл одной комнаты** | `HardReset`/`SuspendMatchListen` рвут всё | **нет** → добавляем |

Маршрутизация: клиент приходит с `JoinRoomRequest{ room = ник, password = 'Dedik' }`
(`MatchCodec.ParseJoinRoomRequestBody`). Пароль не менять — роутим по **нику** через
`PendingRoomAssignment` (ник + `IdentityKey` + IP, TTL). Провал → legacy-комната + громкий лог.

## Шаги

### PR 1 — `RoomRegistry` (фундамент, без сети)

**Файлы:** `server/Net/Match/Kernel/RoomRegistry.cs`, тесты `tests/.../RoomRegistryTests.cs`

- `RoomDescriptor`: `Number` (1,2,3… монотонно, не переиспользуется), `ModeId`, `Level`,
  `Name`, `PasswordKey`, `OwnerNick`, `CreatedUtc`, `State`, `Players`.
- `TryCreate(...)`: валидация режима/карты **только** через `GameModeCatalog` (никаких
  выдуманных карт); «1 ник = 1 комната»; предохранитель от бесконечности (`web.maxRooms`,
  по умолчанию 64 — защита, не игровое правило).
- `TryFind(modeToken, number)`, `List(mode, level)`, `TryRemove(number)`, `ReleaseOwner(nick)`.
- Чистый класс, без сокетов и без HTTP → тестируется в CI как `MatchStartGate`.

**Риск:** нет. **Провод:** нет.

### PR 2 — состояние комнаты из комнаты, а не из глобалов

Сейчас часть состояния — статика на процесс, поэтому две комнаты подрались бы:

| Что | Сейчас | Станет |
|---|---|---|
| `MatchHostSettings.MatchStartArmed` | статика, 17 чтений | `room.Armed` + `IsArmed(room)`; глобальный остаётся для legacy/тестов |
| `WinsNeeded` / `TotalRounds` | статика, 22 чтения | `room.WinsNeeded` из `TryDefaultWinsForMode` при создании |
| `_matchGameModeId` / `_matchSelectedLevel` | поля хоста, 13 чтений | берём из `room.ActorProps[(0,C0/C1)]` (путь уже есть в `HandshakeJoin`) |

**Риск:** средний (трогает решатели конца раунда). Тесты: расширить `MatchStartGateTests`,
`PhaseDurationTests`.

### PR 3 — маршрутизация «ник → комната»

**Файлы:** `server/Net/Match/Host/MatchRoomAssignment.cs` (новый),
`Host/GameMatchHost.HandshakeJoin.cs`, `Host/GameMatchHost.Broadcast.cs`

- `PendingRoomAssignment`: назначение ником + `IdentityKey` + IP, TTL 120 с.
- `HandleJoinRoom`: если по паролю нашли только legacy (`Dedik`) — смотрим назначение и
  сажаем в нужную комнату. Провал → legacy + **громкий** лог, чтобы не выглядело «просто не сработало».
- `EnsureLanRoom()` → `EnsureRoom(roomKey)`; комната создаётся при создании из панели, а не при `/play`.
- Тесты: `RoomRoutingTests` (назначение, просрочка, коллизия ников) — pure.

**Риск: высокий** — единственное место, где можно посадить игрока не туда. После него —
ручная проверка на двух телефонах.

### PR 4 — `/join` в лобби + честный отказ

**Файлы:** `server/Net/GameNetHost.Commands.cs`, `server/Lan/PublicAddress.cs` (новый)

- `/join 2v2 #3` (алиасы: `войти`, `зайти`). **Только из лобби**: `Status == InMatch` → отказ.
- Найдено: `_session` mode/map ← комната, `op9` этому пиру, `Status = InMatch`.
- Не найдено (дословно, как просил):
  `Комната "ranked2v2 #3" не найдена. Создать можно здесь: <адрес>`
  Адрес: `network.advertiseIp` → внешний (только если пришёл не-локальный IP, кэш 10 мин,
  таймаут 2 с) → LAN-IP.
- Тесты: парсер команды.

### PR 5 — жизненный цикл одной комнаты

- Конец катки закрывает **только свою** комнату: `OnMatchOverReturnToLobby` получает
  аргумент-комнату вместо глобального `Action`.
- `HardResetMatchForNewStart(room)` вместо хардкода `Dedik`.
- `SuspendMatchListen` не гасит 7777, пока живы другие комнаты.
- Пустая комната удаляется через `web.emptyRoomTtlSec` (600 с).
- Тесты: чистые решения «пора закрыть / пора удалить».

### PR 6 — `server/Web/` (HTTP-панель)

**Ни одного NuGet-пакета** — только `TcpListener` + минимальный HTTP/1.1 (~250 строк):
`PublishSingleFile` не ломается, размер exe почти не растёт, нативных зависимостей нет.

- `WebServer.cs` — приём соединений, лимиты, статика из embedded resource.
- `WebRouter.cs` — `GET /`, `GET /api/status`, `GET /api/rooms`, `POST /api/rooms`.
- `WebLimits.cs` — **защита от флуда без авторизации**: >10 rps с IP → 429; >5 отказов
  за 10 с → пауза 60 с; заголовки ≤ 8 КБ, тело ≤ 4 КБ, таймаут 5 с, ≤ 2 соединений с IP.
- `StatusSnapshotCache.cs` — снимок раз в секунду с тика; HTTP **никогда** не берёт
  блокировки горячего пути (тот же приём, что `MatchPerf`).
- `wwwroot/index.html` — макет из `.panel-mock/` (Material You, tonal-spot палитра),
  вшивается как `<EmbeddedResource>`; URL **только относительные** (`./api/...`).
- Конфиг: `web { enabled, bindAddress = "127.0.0.1", port = 8080, maxRooms = 64,
  emptyRoomTtlSec = 600, publicBaseUrl = null }`.
- **Создание комнат — только с сайта** (консольной команды нет, как ты просил).
- Тесты: `WebHttpTests` (парсер запроса), `WebLimitsTests` (токен-бакет), `WebJsonTests`.

### PR 7 — документация

- `README.md` — раздел «Комнаты и веб-панель», честные лимиты.
- `ARCHITECTURE.md` — новый слой `server/Web/`.
- `deploy/nginx-subpath.conf.example` — **только `example.com`**.
- В коде/доках/тестах **нет** реальных адресов и доменов: внешний адрес живёт в
  `config.json` (`web.publicBaseUrl`), а он в `.gitignore`.

## Порядок и проверка

1 → 2 → 3 → 4 → 5 → 6 → 7. PR 3 и 5 — после ручного теста на двух телефонах.

**Локально собрать нельзя** (в песочнице нет .NET SDK и закрыт `dotnet.microsoft.com`),
поэтому:
- синтаксис C# проверяется парсером (tree-sitter) до коммита;
- сборка и тесты — CI на GitHub (`build` × 3 ОС + `dotnet test`);
- PR-ы маленькие, чтобы красный CI показывал один шаг, а не семь.

## Состояние на 2026-11-14

Все семь шагов написаны и лежат в PR #48 (ветка `arena/ddbade03-vlalchillow`).

- `build` (ubuntu, windows, macos) — зелёный: сервер собирается, 451 тест проходит.
- Страница панели — 31 проверка в `tests/panel/panel.test.js` (jsdom, вне CI: нужен Node).
- `format (advisory)` красный и на `main` — это не регрессия от этих изменений.
- Парсер C# (tree-sitter) — 199 файлов, 0 ошибок.

Что нашлось и починено уже на этапе CI (не «на глаз»):

- `Utf8JsonWriter` по умолчанию экранирует кириллицу в `\uXXXX` — в панели ник
  «влал» выглядел как мусор. Один `JsonWriterOptions` с `UnicodeRanges.All` на весь
  веб-слой (`server/Web/JsonText.cs`).
- `LanAddressProvider = () => null` проваливался в реальные сетевые интерфейсы:
  тест зависел от машины и падал на CI-раннере, где LAN-адрес есть. Заданный
  делегат теперь окончательный ответ.
- Номер комнаты после неудачного создания **не** переиспользуется — это намеренно,
  иначе `/join 2v2 #3` стал бы означать другую катку. Тест описывал обратное.

Остаётся за пределами кода: на сервере поднять процесс, положить `config.json`
с `web` (панель на `127.0.0.1:8080`) и применить `deploy/nginx-subpath.conf.example`.
До этого `https://<домен>/vlalchillow/` отдаёт 502 — location есть, бэкенда нет.
