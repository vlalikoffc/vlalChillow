# Веб-панель комнат

Панель — это часть того же исполняемого файла, что и сервер. Отдельного бинарника,
отдельного конфига и отдельного порта для игры нет: комнаты мультиплексируются на одном
игровом сокете, а панель лишь читает их состояние и умеет создать комнату.

```
игрок ──браузер──> nginx ──> 127.0.0.1:8080  (панель, TCP)
игрок ──игра────> UDP 7777   (матч,   НЕ меняется)
игрок ──игра────> UDP 7778   (лобби,   НЕ меняется)
игрок ──игра────> UDP 5056   (discovery, НЕ меняется)
```

## Что умеет

| Действие | Как |
|---|---|
| Посмотреть, кто онлайн | Открыть страницу |
| Посмотреть комнаты | Вкладка «Публичные комнаты», фильтры по режиму и карте |
| Создать комнату | Одна кнопка: режим, карта, имя |
| Позвать друзей | Кнопка «скопировать» даёт `/join 2v2 #3` |
| Зайти в комнату | В игре, в лобби-чате: `/join 2v2 #3` |

Создание комнаты возможно **только** с сайта. Команд вида `/create` в игре нет и не
будет: кнопка — это единственный вход.

## Настройка

В `config.json`, секция `web`:

```json
{
  "web": {
    "enabled": true,
    "bindAddress": "0.0.0.0",
    "port": 8080,
    "maxRooms": 64,
    "emptyRoomTtlSec": 600,
    "publicBaseUrl": "",
    "limits": {
      "requestsPerSecond": 10,
      "refusalsBeforeBlock": 5,
      "refusalWindowSec": 10,
      "blockDurationSec": 60
    }
  }
}
```

- `bindAddress` по умолчанию `127.0.0.1` — снаружи только через nginx. `0.0.0.0`
  нужен, если играете по локальной сети без прокси.
- `publicBaseUrl` — адрес, который называется игроку в ответе «комната не найдена».
  Пусто — сервер определит сам (внешний IP, затем LAN). **Настоящий домен вписывается
  здесь, на машине владельца, и не попадает в репозиторий.**
- `maxRooms` — предохранитель, а не правило. Правило — одна комната на игрока.

## nginx

Готовый блок: [`deploy/nginx-subpath.conf.example`](../deploy/nginx-subpath.conf.example).

```nginx
location = /vlalchillow { return 301 /vlalchillow/; }

location /vlalchillow/ {
    proxy_pass http://127.0.0.1:8080/;   # слэш в конце срезает префикс
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    client_max_body_size 16k;
    proxy_read_timeout 15s;
}
```

Проверить и применить:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## Если nginx на другой машине

Самая частая причина 502 при живом сервере: панель слушает `127.0.0.1`, а прокси
стучится на сетевой адрес (например, `192.0.2.10:8080`) — это разные интерфейсы,
соединения не будет.

- `web.bindAddress` должен быть `"0.0.0.0"` (это дефолт, менять не нужно);
- в `proxy_pass` — адрес машины, где запущен сервер:
  `proxy_pass http://192.0.2.10:8080/;`
- `proxy_pass` с путём (`/`) срезает префикс `/vlalchillow/`, панель получает
  `/api/rooms` — так и задумано.

Проверка с машины с nginx, до правки конфига:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' http://192.0.2.10:8080/healthz
```

`200` — сеть в порядке, дело в nginx. Отказ соединения — панель слушает не тот
интерфейс (или не запущена).

При старте сервер сам печатает адреса, по которым панель реально открывается:

```
[web] панель на порту 8080 (комнат до 64, лимит 10 запр/с с IP)
[web]   с телефона (та же сеть): http://192.0.2.10:8080/
[web]   на этой машине:         http://127.0.0.1:8080/
```

## Если открывается 502 Bad Gateway

nginx жив, но за ним никто не слушает. Проверяй по порядку:

1. Запущен ли сервер и что он напечатал на старте:
   ```
   [web] панель на http://127.0.0.1:8080/ ...
   ```
   Если вместо этого `[web] панель НЕ поднялась: ...` — в причине уже написано, что не так.
2. Не занят ли порт старым процессом: `ss -ltnp | grep 8080`.
3. Совпадает ли порт в `proxy_pass` с `web.port`:
   `grep -A3 'location /vlalchillow' /etc/nginx/sites-enabled/*`.
4. Не выключена ли панель: `"enabled": true` в `config.json`.

Панель **не** падает, если занят игровой порт 7777: страница откроется и покажет
предупреждение. Это специально — иначе «сервер не запустился» выглядело бы как
«сайт сломался».

## API

Панель отдаёт JSON — им пользуется её же страница, но можно и своим скриптом.

### `GET /api/status`

```json
{
  "onlineLobby": 2, "onlineMatch": 5, "onlineTotal": 7,
  "roomsCount": 3, "roomsMax": 64, "nextNumber": 4,
  "gameListening": true, "matchRunning": true,
  "mode": "Ranked2v2", "levels": "Sandstone 2x2",
  "serverUtc": "2026-11-14T12:00:00.0000000Z"
}
```

Собирается раз в секунду и отдаётся из кэша: запросы панели никогда не заходят в
горячие блокировки игрового цикла.

### `GET /api/rooms`

```json
{
  "nextNumber": 4, "count": 3, "maxRooms": 64,
  "rooms": [
    { "number": 3, "mode": "Ranked2v2", "modeName": "Союзники",
      "level": "Sandstone 2x2", "name": "вечерняя", "owner": "влал", "ownerId": 47021139,
      "state": "live", "players": 4, "joinCommand": "/join 2v2 #3",
      "perTeam": 2, "maxPlayers": 4, "teamLabel": "2 на 2",
      "createdUtc": "2026-11-14T11:59:00.0000000Z" }
  ]
}
```

`state` — `waiting` | `live` | `finished`.

### `GET /api/modes`

Режимы и карты из каталога сервера. Страница берёт список отсюда, а не хранит копию:
копия неизбежно разъехалась бы с `GameModeCatalog`.

### `POST /api/rooms`

```json
{ "mode": "2v2", "level": "Sandstone 2x2", "name": "вечерняя", "ownerId": 47021139 }
```

`mode` — алиас или id (`2v2`, `Duel`, `tdm`…), `level` и `name` можно опустить.

**Владелец задаётся ID, а не ником.** Ник в лобби не уникален и его можно вписать
любой, поэтому сервер принимает только число — тот самый ID, который клиент получает
в чат лобби при входе («Ты <ник> · ID: …»). Сервер сверяет ID со списком тех, кто
прямо сейчас в лобби, и ник для подписи берёт из своего списка. Нет такого ID —
комната не создаётся, клиенту говорят «не в сети».

| Ответ | Когда |
|---|---|
| `201` | Комната создана, в теле `joinCommand` |
| `400` | `unknown_mode`, `unknown_level`, `empty_owner` (нет `ownerId`), `nick_not_supported` (прислали ник вместо ID), `bad_json` |
| `409` | `player_offline` (такого ID нет в лобби), `one_room_per_player`, `too_many_rooms` |
| `429` | Слишком часто; смотри `Retry-After` |
| `500` | `room_not_created` — игровая комната не поднялась, запись откатана |
| `503` | `room_limit` — кончились номера комнат |

## Флуд-защита

Паролей и куки нет — спека требует «одну кнопку». Поэтому защита только по адресу:

- больше **10 запросов в секунду** с одного IP → `429` с `Retry-After`;
- **5 отказов** за 10 секунд → пауза **60 секунд** на этот адрес;
- не больше **2 соединений** одновременно с одного IP;
- заголовки ≤ 8 KB, тело ≤ 4 KB, запрос целиком ≤ 5 секунд.

Человек с одним браузером этих чисел не замечает: страница делает два запроса в секунду.

## Ограничения

- Комнаты живут в памяти: перезапуск сервера их закрывает. Это осознанно —
  номер комнаты выдаётся один раз и после рестарта начинается заново с 1.
- Номер комнаты — **наименьший свободный**: открыты #1 и #3, новая получит #2.
  Переиспользуется только номер закрытой комнаты, поэтому `/join 2v2 #3` не может
  указать на две живые катки одновременно.
- Одна комната на игрока (ключ — ID, не ник). Это резерв места, а не потолок.
- Потолок комнаты зависит от размера команд: 1 на 1 — двое, 2 на 2 — четверо,
  6 на 6 — двенадцать, режимы без деления — 16. `maxPlayers` и `teamLabel`
  приходят и в списке, и в ответе создания, чтобы счётчик `4/4` не врал.
- `players` в панели — число живых людей в комнате, без «серверного» актора.
- `"enabled": false` не мешает игре: панель просто не занимает порт, UDP и
  обнаружение работают как обычно.
- Когда пустая комната убирается по `emptyRoomTtlSec`, вместе с ней снимается
  и бронь владельца — игрок может создать комнату снова.
